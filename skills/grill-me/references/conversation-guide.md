# Ask a few useful questions

Use this guide when discovery starts or the user chooses a recommendation.

## Start from what is known

Read the user's request and earlier answers. Use supplied evidence before asking for facts it can establish. Ask only for information that changes the next step.

For a new request, cover these topics only when they are missing:

1. Ask what repeated task takes effort or causes delays. Ask who does it if that changes the recommendation.
2. Ask whether to use their description or review a selected source. A description needs no connected account.
3. For a connected scan, ask which repository, base, conversation, or email search to review. Ask for the activity window if it is missing.

Usually two or three answers are enough. A clear request may need none. A missing source limit must be resolved before that source is read. Do not use a broad account search as a default.

## Use each answer

Ask one question per turn. Wait for the answer. Use a question tool if the host provides one. Otherwise ask in the conversation.

Briefly state what the answer changes when that helps the user. Then continue the analysis or ask the next unanswered question. Do not repeat the entire conversation after every answer.

Offer a suggested answer or a small set of choices when there is a useful basis for them. Explain the reason briefly. A suggestion is not a confirmed rule. Do not invent a recommendation for an unknown fact, such as which repository the user owns.

When the user corrects an answer, replace the earlier answer. Revise any recommendation or specification affected by the correction. Do not keep both as confirmed decisions.

When the user says “I do not know,” mark the answer unknown. Use a reasonable provisional option only when it leaves business rules unchanged. Keep any required decision visible before calling the specification ready to build.

## Move from recommendations to a specification

Present supported recommendations once the task and source limits are clear. Invite the user to choose one workflow. Keep its ID, evidence, existing automation coverage, and known answers.

For a selected workflow, use the bundled Grill Me skill. Ask about two to four important unanswered decisions. Common topics are the trigger, included work, output destination, required review, and exceptions. Skip topics already settled. Ask fewer questions when enough is known.

Ask more only when an unresolved choice prevents an accurate specification or the user requests a deeper interview. Explain why a further question is needed. Do not require a fixed number of questions in each topic.

Once enough is known, write the specification and outcome checks. Mark missing source mappings and unconfirmed choices. Do not treat silence as approval.

## Pause, stop, or request discovery only

For “discovery only,” provide recommendations without asking the user to select a workflow or starting its interview. Ask only for missing limits required to perform the requested scan.

For “pause” or “stop,” end the questions. Return the selected workflow, confirmed answers, unresolved choices, current topic, and next question if one remains. Resume from that point when requested.

Selecting a recommendation authorizes this discussion. It does not authorize building, deploying, changing records, or sending messages.
