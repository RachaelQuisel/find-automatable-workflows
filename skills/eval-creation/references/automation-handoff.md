# Automation handoff

Read this only when a selected automation opportunity or its specification is already in the conversation.

Read the selected workflow and specification from the conversation or the supplied [handoff format](handoff-format.md). Preserve the goal, rules, evidence, existing coverage, and unanswered questions.

The plugin proposes checks. It does not run the proposed automation. Without actual run evidence, use Needs review and Not run. Writing or reviewing a proposed evaluation is not an execution attempt. Missing evidence is not an observed failure.

The ten-attempt limit applies to evaluation. Past ten full runs, repeated retries usually hide a design problem. It does not set operational retries for the proposed automation. The user defines that automation's stop and retry behavior. Keep an unknown policy unresolved.

Deliver the specification and eight-section evaluation together. Recommendation usefulness and business rules require user judgment. Complete fields or an accepted tool request alone do not prove the business result.
